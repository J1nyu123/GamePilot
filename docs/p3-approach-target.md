# P3 可见目标接近实验

日期：2026-10-14。实现阶段：反馈技能、独立 Verifier 与 Runner 已拆分，支持直接技能和 Agent 两条路径。P4 的实机退出条件仍未完成。本次不把 P3 样例混入 P4，也不宣称实机成功率或跨场景泛化。

## 使用

重启 GamePilot，选择《塞尔达传说：旷野之息》的 Cemu 窗口并预览，连接已配置的真实 Xbox 输入。右侧模型工具选择“P3 目标接近实验”。默认仍是模拟模式，切换实验模式不会自动执行。

填写一个唯一、始终可见的目标描述，例如明确位置的石柱，而不是“前面的东西”。固定摄像机朝向，在无遮挡、无战斗、无悬崖的简单路径测试。操作者手工恢复同一初始存档位置及镜头，不自动操作存档或游戏配置。

配置到达区域和最小目标面积：

- 坐标为截图归一化 `[x,y,width,height]`，左上为 `(0,0)`，右下为 `(1,1)`。
- 默认区域 `[0.35,0.20,0.30,0.65]`；判断目标框中心是否在区域内。
- 默认最小面积 `0.06`，即目标框的 `width × height` 至少占截图 6%。
- 成功条件还须填写具体可见描述；宿主会将目标、区域、面积及附加条件合成为固定判据保存。

这些是屏幕视觉条件，不等于真实世界距离或角色确实到达某米数。目标本来就满足条件的只读成功不算移动接近正例。阈值在重复实验前固定，不根据结果临时调低。

选择执行路径：保留默认的“Agent 选择技能”，或选择“直接执行技能”。两条路径都在点击运行后有 3 秒切换到 Cemu 的准备时间；模式切换不执行动作。Agent 通过通用工具注册调用 `approach_target(targetId, observationId)`，只可引用固定目标及最新观察；直接路径跳过 Planner 请求。目标、坐标标准、力度、步长和预算由宿主冻结，不暴露低层输入或任意代码接口。Agent 的完成声明不能产生任务成功。

## 技能内部反馈

1. 先确认归零，建立捕获屏障并获取新帧。
2. 独立定位请求比较初始参考图、上一帧及当前帧，返回目标框、是否同一目标、场景/路径状态与置信度。
3. 校验窗口身份、新帧、坐标、场景、目标身份和状态有效期。
4. 目标偏左/右时短暂向左/右移动；水平对齐但面积不足时向前移动。目标面积达标但垂直位置无法满足时停止，不自动旋转镜头。
5. 每段执行后等待 neutral ACK，再取新帧重新定位。等待模型时手柄保持归零。
6. 连续两个不同新帧满足区域/面积且观测间隔不少于 300ms，技能归零并返回到达候选，不进行最终验证。
7. Runner 调用独立 GameVerifier，根据冻结标准逐项给出 passed/failed/inconclusive 与帧引用。failed 表示当前未完成，允许在剩余运行预算内重新取帧或有限纠偏；inconclusive 和安全受阻停止，不盲移。
8. 独立验证 passed、证据有效且目标一致、未取消及最终释放/落盘检查均通过，运行才为 succeeded。Agent 后续总结失败单独记录，不覆盖有效验证；取消或证据过期可保留历史 passed，但运行不会标记 succeeded。

首版定位后端复用现有 pi-ai/VLM，不新增大型检测库。状态包含递增版本、observationId、固定 targetId、源采集时间及 Main 单调时钟有效期。置信度来源固定标为 `vlm-self-report`，它未经概率校准；同一模型做定位和验证也不意味着错误互相独立。

## 固定限制

| 限制 | 值 |
| --- | --- |
| 每次运行技能调用 | 受剩余观察、动作及时间预算约束；最多 6 次到达候选调用，应用内 Agent 保留最多 3 轮决策/总结约束 |
| 短动作 | 整次运行累计最多 8 段，每段 200ms，左摇杆力度 0.35；再次调用技能不重置预算 |
| 总有界移动请求 | 最多 1600ms；模型等待期间不保持输入 |
| 反馈观测 | 整次运行最多 12 次，取帧尝试也占用预算 |
| 反馈运行总超时 | 60 秒，覆盖技能、验证和 Agent 总结，另受整个任务总超时约束 |
| 状态有效期 | 从本次取帧请求之前开始计时，8 秒；包含采集、落盘和 VLM 定位耗时 |
| 最低自报置信度 | 0.85 |
| 连续性保护 | 中心跳变 >0.35 或面积比超出 1/3–3 时停止 |
| 完成证据年龄 | 不超过 15 秒，包含独立验证和 Planner 后续回复 |

真正发送输入前，在异步窗口焦点检查完成之后再同步检查状态有效期，避免“检查时有效、发出时已过期”。慢模型可能导致 stale-state；保留该结果，不延长 TTL 假装新鲜。

目标丢失、身份不确定、低置信度、路径不清楚、菜单/场景变化、旧帧、状态过期、预算/超时均停止；分别记录受阻、预算耗尽或超时。输入释放失败则保留故障，不能伪装安全结束。F8、取消、失焦和关闭继续经过现有输入租约与归零链路。P3 不提供技能内暂停续跑；可以取消或安全接管，重新实验须手工恢复场景并保留上一结果。

## 运行证据与审计

新 P3 manifest 为 schemaVersion=3，保存冻结 task、逐项 criteria 与 executionStrategy；旧 schemaVersion=2 不回写，仍可审计。`experiment.kind=p3-approach` 保存完整目标配置和固定限制；P4 报告拒绝这类记录。Trace 保存初始及每次反馈关键帧，事件包括：

| 事件 | 用途 |
| --- | --- |
| tracking_start / tracking_state | 定位请求、目标框、版本、有效期、置信度来源 |
| approach_decision | 新帧所支持的方向或保持决策 |
| approach_step | 申请一个有界移动段 |
| approach_input | 焦点检查后、真正发送前的状态年龄和版本 |
| skill_released | 本段执行及归零回执 |
| approach_end / runner_execution | 单次技能结果 / 跨调用累计统计 |
| verification_end / runner_end | 独立逐项验证 / 运行状态、任务结论和停止原因 |
| skill_execution_start / skill_execution_end | 直接路径执行记录；Agent 路径使用 tool_execution 记录 |

summary.runResult 分开记录 status、taskOutcome 和 stopReason，并保留验证观察时点及独立的 Agent 总结错误。summary.approach 区分尝试段数 steps、已执行并确认归零段数 executedSteps、反馈次数和已确认执行的方向改变次数 corrections。右侧反馈卡可展开定位和纠偏证据，左侧关键帧可逐张核对。

```powershell
cd D:\work\GamePilot
npm run audit:p3 -- --run <运行UUID>
```

审计检查配置、原运行结构、状态版本、新帧引用、发送前有效期、决策方向、预算、连续保持和独立判据。`feedbackDemonstrated=true` 表示存在依据不同新帧改变输入方向且有执行归零确认的记录，不证明模型正确识别目标。`testData=true` 不能作为实机证据；`humanReview=required` 始终保留。

## 实机实验标准

在相同初始场景、镜头、目标和固定条件下保存至少 5 次完整接近实验，移动后成功至少 4/5；保存所有失败，不只选绿色结果。其中应有需要横向修正再向前移动的场景，使证据可证明实际纠偏。另做目标丢失、过期状态、技能超时和取消停止实验。

与冻结原型在同一初始场景配对比较：成功率、耗时、动作段数/输入时间、方向修正、目标丢失、模型调用及观测年龄。原型使用自身有界开环任务，必须记录任务与配置差异；不能把新模型或不同初始位置的收益归因于反馈控制。

记录表见 `benchmarks/p3-experiment-template.md`。本次开发只提供自动测试及受控桌面联测，不自动运行真实游戏、不填写虚构的实机结果。

### 操作台交互提示验收

界面默认开启“到达时必须出现该目标的交互按键和文字提示”。该选项写入本轮固定配置与审计。定位器逐帧返回 `interaction.status`（present/absent/unknown）和可见提示原文；通用移动/视角帮助不算交互提示。

区域与面积达标但提示明确不存在时，技能在原预算内继续前进；提示缺失或无法判断时停止为 `interaction-unknown`。只有区域、面积和目标交互提示连续两帧均达标才调用独立验证器。仍然整次运行最多 8 段、每段 200ms；只有有效的 failed 验证才允许在剩余预算内再次调用技能，不执行交互。取消勾选可运行原来的纯屏幕面积实验。旧配置未指定该选项时保持原行为。

该改动不保证一次走到目标：步预算、定位延迟、提示歧义仍可能导致停止；真实游戏验收仍需执行。
