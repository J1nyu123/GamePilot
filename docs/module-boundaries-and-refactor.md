## 现状与目标

P3 已有实机续程成功样例，但固定起点重复验收和 P4 正式验收尚未完成。重构前的耦合主要位于实验入口、Agent 调度、结果判定和审计：runtime/p1/src/runtime.mjs 内置 P3 专属工具与提示词；main/ipc.ts 组装实验并强制经 Agent 启动；ApproachTarget.finalize 依赖 Agent 的 control_passed；审计要求一次 approach_target 工具调用。现已移除这些 P3 耦合；P1/P2 与 P4 保留兼容入口和原验收标准。

目标：Experiment 定义怎样测试，Agent 决定怎样做，Skill 执行动作，Verifier 判断任务有没有完成，Runner 决定何时继续或结束。固定实验可以直接调用技能，无须强制经过 Agent。

## 模块职责与边界

| 模块 | 职责 | 禁止承担的职责 |
| --- | --- | --- |
| Experiment | 固定任务、起始条件、成功标准、参数、预算、重复次数和基线；调用 Runner 并汇总试次 | 不决定移动方向、不控制设备、不判定单次成功 |
| Runner | 单次运行生命周期；组装依赖、调度执行与验证、维护全局预算、取消及结束检查 | 不做视觉推理，不用动作执行成功推断任务完成 |
| Agent | 根据任务、观察和验证反馈选择下一技能；通过通用工具接口提出动作 | 不修改成功标准、不绕过预算、不发布权威成功结论 |
| Skill | 有边界的动作或反馈控制；报告动作回执、到达候选、受阻或局部预算耗尽 | 不调用最终任务验证，不依赖 Agent 总结或最终状态，不独立宣布任务成功 |
| Observation / State Estimator | 获取截图并维护来源、时间与有效期；估计目标框、提示、置信度与状态版本 | 不判定整体任务完成；模型自报置信度不等于校准概率 |
| Verifier | 根据固定标准和证据独立回答任务是否完成，逐项给出判定及引用 | 不执行动作、不规划路线、不修改标准、不采信 Agent 自述为完成证据 |
| Input Controller | 输入租约、发送、执行与归零回执、失焦保护、取消和紧急停止 | 不理解任务成功条件 |
| Trace / Reporter | 记录配置、观察、动作、验证和停止原因；生成可追溯报告 | 不重新推断成功，不把模型自由总结当事实，不把 evidence-check 写成独立视觉验证 |

IPC 只负责输入校验和调用应用服务，不承载具体实验编排。界面只编辑配置和呈现运行结果，不成为成功判定源。

## 公共契约与 Verifier

契约先行：TaskSpec（不可变目标与标准）、Observation（证据身份/来源/时间）、ExecutionResult（执行结果）、VerificationResult（任务判断）、RunResult（运行状态与任务结果分别保存）。同一 run 内任务身份和成功标准不得改变。

Verifier 输入：固定任务及逐项成功标准、初始和最新证据、必要的连续帧、时间/窗口身份/释放回执等元数据。不依赖 Agent 对话或推理。动作历史用于关联证据，不能证明任务完成。

建议输出结构（设计草案，非现有接口声明）：

```ts
type VerificationResult = {
  verdict: 'passed' | 'failed' | 'inconclusive';
  criteria: {
    id: string;
    verdict: 'passed' | 'failed' | 'inconclusive';
    evidenceIds: string[];
    reason: string;
  }[];
  summary: string;
};
```

实际实现须保留验证 ID、任务 ID、证据引用、验证方法与耗时等审计信息。先做确定性的证据有效性检查，再进行视觉标准判断；未调用视觉模型时须明确标记 evidence-check。

- passed：全部必要条件有充分证据支持。
- failed：有效证据明确表明至少一个必要条件当前未满足。
- inconclusive：证据缺失、过期、模糊或冲突，无法判断。

failed 是“当前未完成”，不自动等同于本次运行必须结束。Runner 根据预算、取消、安全状态和失败原因决定是否允许下一轮；Agent 或直接执行策略决定下一动作。禁止无上限重试。

## 执行状态与任务结果分离

| 场景 | 执行/运行状态 | 任务结果 |
| --- | --- | --- |
| 动作正常结束，验证确认无交互提示 | 正常执行，可由 Runner 决定继续 | failed |
| 预算耗尽，未调用 Verifier | budget-exhausted | unverified |
| 证据检查无法确认 | 受阻或正常结束，记录具体原因 | inconclusive |
| Verifier 通过且结束检查通过 | succeeded | passed |
| 验证通过后 Agent 总结失败 | 单独记录总结错误 | 保留有效验证结果 |
| 用户取消或输入归零未确认 | canceled 或 failed | 保留已有验证证据，但不得将运行标记为 succeeded |

Runner 的成功结束门槛仍包括：验证证据有效、目标一致、输入归零确认、未取消。解除 Agent 总结依赖不等于移除这些检查。结果必须指明验证覆盖的是哪个观察时点；过期结论不能证明后续状态。

## P3 流程映射

1. State Estimator 输出目标位置、提示状态及提示原文，通用移动帮助不算目标交互提示。
2. Approach Skill 执行有限短移和纠偏，在到达候选条件时归零并返回执行结果。
3. Runner 组织动作后新帧/连续证据，调用 Verifier。
4. Verifier 独立检查“指定操作台对应的交互按键及文字提示”等冻结条件。
5. Runner 在 passed 时进行结束检查；未通过时仅在剩余预算和安全条件允许时继续，否则记录停止原因。
6. Reporter 基于结构化记录描述结果，不宣称未发生的验证。

## 拆分顺序与验收门槛

每一步保持旧链路可运行；用适配器渐进迁移，不同时替换全部模块。

| 顺序 | 实施内容 | 完成门槛 |
| --- | --- | --- |
| 1 公共契约 | 定义上述任务/观察/执行/验证/运行类型；冻结成功标准；保留旧字段适配 | 执行成功不能直接映射任务成功；旧日志可读取 |
| 2 独立 Verifier | 复用 GameVerifier，输出逐项结果，移除 Agent 对话依赖 | passed/failed/inconclusive、过期证据、目标错配与模型口头成功声明均有验证覆盖 |
| 3 收窄 Skill | 移出 ApproachTarget 内的最终验证和 finalize(Agent结果)；保留反馈与局部限制 | 可直接测试/执行技能；到达候选不自动成为任务成功；取消与归零仍有效 |
| 4 提取 Runner | 从 IPC 抽取编排；统一调用技能、取证、验证和结束检查 | 先保持单轮行为，再支持预算内继续；再次调用技能不得重置 run 总预算 |
| 5 Agent 可选 | 通用工具注册与适配器替换 P3 专属分支；支持直接技能与 Agent 两种执行路径 | 两条路径使用同一 Verifier、安全约束及结果语义；Agent 总结失败不篡改有效验证结果 |
| 6 提取 Experiment | 只管理配置、起点、重复试次、基线与统计，通过 Runner 启动 | 不导入 Agent 具体实现；更换执行策略不要求修改实验组织逻辑 |
| 7 审计/UI/验收 | 审计执行与验证证据，移除必须一次 Agent 工具调用的通用前提；分开展示状态与结论 | 直接执行和 Agent 路径均可审计；成功、预算耗尽、取消、过期和验证失败回归通过 |

优先完成 1–4，解除“技能结果依赖 Agent 最终状态”的核心耦合。第 7 步是最终整合；各阶段所需的审计与 UI 兼容同步完成，不能把安全验证留到最后。

预算由 Runner 跨调用累计；技能只在分配额度内执行。配置化或增加预算属于独立变更，不能借拆分默默放宽当前 8 段、200ms、有效期与紧急停止约束。保留旧运行记录，不回写历史结果。
